    Class PlcReadLengthGuard

    读长度的窄化守卫。

    【缺陷背景】点表 TagItem.Length 来自 XML（`TagItem.LoadByXmlElement` 只有 `int.Parse`， **没有任何范围校验**），而字符串读路径把它 `(ushort)` 窄化后交给驱动 （`ReadStringAsync(address, (ushort)readLength, …)`）⇒ 例如 `Length = 100000` **静默回绕成 34464** ⇒ **读错长度、返回错值，且不抛异常、不告警**。

    【为什么"响亮失败"而不是"钳位"】钳位（截到 65535）仍然是**静默读错** ✗； 而越界 `Length` 的当前行为本就是**未定义的错误值** ✗ ⇒ 换成**明确失败**属于 “消除静默错误” ✓，不是改变一个被正确依赖的语义 ✓。

    【为什么单独成类】字符串读路径有**多处**（`DevicePro`、`BatchMonitor`、 `DeviceBase`），逐处各写一遍判定必然漂移 ⇒ 统一收口到这里， 且它是**纯函数** ⇒ 可离线单测（`InternalsVisibleTo("ZL.IotHub.Tests")` ✓）。

    TryResolveReadLength(int, out ushort)

    把点表配置的字符串读长度（字节）解析为可用的 ushort 读长。

    语义：configuredLength ≤ 0（未配置 / UI 传 -1）⇒ 1（**既有语义，不变** ✓）； 1..65535 ⇒ 原值 ✓；**> 65535 ⇒ 返回 false**（调用方**必须响亮失败**，不得继续用回绕值 ✗）。
