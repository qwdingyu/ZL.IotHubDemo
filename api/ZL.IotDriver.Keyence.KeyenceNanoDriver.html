    EndianConverter

    字节序：大端 + CDAB 字序（RegularByteTransform 同口径）。

    【依据 ①】线下帧层面：字组装 `(hi<<8)|lo` ⇒ **16 位大端** ✓（与仿真器一致）

    🔴【依据 ②，2026-11-03 交叉测试字节级实测，推翻"纯 ABCD"】： 收尾交叉测试把本协议加进 `MergedBlockProtocolCrossTests` 混合类型用例后 **int16 通过、int32 失败**（写 -123456789 读出 854325412 = 恰为一个**字交换**）。 字节级取证（我方写 → 读原始字节；HSL 写 → 读原始字节）： 

    我方 ABCD 写 0x12345678 → 内存 [12 34 | 56 78]
HSL     写 0x12345678 → 内存 [56 78 | 12 34]   ← 字序相反
而两者写 int16 0x1234 都是 [12 34]            ← 16 位完全相同

    HSL KeyenceNanoSerialOverTcp 的字节变换为 new RegularByteTransform() （反编译 KeyenceNanoSerialOverTcp 构造函数，KeyenceNanoSerialOverTcp.cs:19），其 16 位不受 DataFormat 影响、 32 位按字序重排 ⇒ 实际约定 = 16 位大端 + 32 位字交换。

    ⇒ `CdabEndianConverter` 正是这个语义（其注释明写"ABCD/CDAB 的 16 位是大端"）， 纯 `BigEndianConverter`(ABCD) 会在**双字**上双向字交换 ✗ ⇒ 以**实测**为准（AGENTS §22.4）

    ⚠️ 同类先例：`MemobusTcpDriver`（2026-10-28）、`YokogawaDriver`（2026-11-03） 均因**完全相同的原因**（int16 对 / int32 字交换）改用 CDAB ✓

    ⚠️ 证据性质：来源是「真实 HSL 客户端行为 + 字节级实测」⇒ **B 级（HSL 单源）**， **没有**基恩士官方手册背书；真机验证仍缺 ✗
