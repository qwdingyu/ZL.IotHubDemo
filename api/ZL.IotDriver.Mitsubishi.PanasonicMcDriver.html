    Class PanasonicMcDriver

    松下 MC 协议驱动。基于三菱 MC 协议，松下 FP 系列使用。 地址格式：R0（内部继电器）、X0（输入）、Y0（输出）、D0（数据寄存器）、L0（链接继电器）、W0/DT0（报警/数据）。 默认端口：6010（历史默认，无官方依据）。

    ⚠️ 官方 FP7 Ethernet Expansion 手册 §9.1.2 明确 MC 协议 Home port number 5000 (Recommended)；6010 在本仓未找到任何官方原文支撑。 为不破坏既有现场点表/直连代码，**保留 6010 为默认值**，但不再声称“松下标准”； 新项目建议显式配置 5000（或按设备实际监听端口）。

    ParseAddress(string)

    松下 MC 地址解析。

    松下与三菱共用 MC 协议帧格式，但部分软元件的进制/TypeCode 不同。 主体委托给基类，仅拦截有差异的分支。

    【X/Y/R/L 的 packed 地址】松下与三菱**不是简单换一个进制** ✗： 官方 MEWTOCOL 手册（WUME-MEWCP-03 1.1）规定 X/Y/R/L 的 **末位是十六进制、前面各位是十进制** ⇒ `X10`=`1×16+0`=**16**、 `X100`=`10×16+0`=**160**；点号 `R10.5`=`10×16+5`=**165**。

    【L/R TypeCode 差异】松下 L/R 的 TypeCode 与三菱不同： 

    三菱 L = 146, BitType=1
松下 L = 160, BitType=1
三菱 R(Qna_3E) = 175, BitType=0
松下 R = 144, BitType=1   // 内部继电器（位），不是三菱的文件寄存器

    Format 字段是源码表元数据，不能用它反推地址（packed 无法用单一 radix 表示）。

    【为什么不改基类】这些差异仅存在于松下 MC 分支，改动应局限在 PanasonicMcDriver 内，避免把三菱/基恩士等驱动一起拉进回归风险。
