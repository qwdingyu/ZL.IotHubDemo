    Enum PlcAddressProfile

    PLC 地址解析的协议画像枚举。 不同厂商 PLC 的地址书写习惯差异很大（如西门子用 DB1.DBX0.0，三菱用 D100）， 通过指定 Profile 可以优先按目标协议解析，避免歧义。

    【2026-10-21 新增】名称型寻址：地址原样作为"标签名 / JSON 路径 / 数据项 id" ✓， 不做任何格式归一化（尤其不统一大写 ✗）。

    【为什么要它】`ISSUES §二十七`/`§二十四` 实测：AB 符号名 `MyTag`、 `URL|JSONPath`、MTConnect `$.Devices[0]` 等**原生形态**落在原地址模型之外 ✗ ⇒ 被建块器排除 ⇒ **点位永不读取** ✗。而它们的驱动本就**原样**使用地址 ✓ （实测 `HttpRestDriver`/`MTConnectDriver` 把 `address` 交给 `ExtractJsonPath(address)` ✓） ⇒ 正确的语义就是"不解析、原样透传" ✓。

    ⚠️ 与 `PreserveSourceAddress`（`NativeProtocolDescriptor`）**配套使用** ✓： 前者让地址**能进**建块器 ✓，后者让驱动拿到**原始串**（而非拼接结果 ✓）。
