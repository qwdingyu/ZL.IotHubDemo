    TypedAccess

    字节透明（一处声明同时决定读/写/位读三面）—— 本驱动不编解 BCD、不理解数据语义（见文件头）。

    [!!] 值区是 **BCD、低字节在前**，每 DI 的小数位不同（水表/热量表/燃气表各异） ⇒ 若按 `ushort`/`float` 解释必得静默错值；写侧同样会把 `2311` 编成 `09 07` 而表要 `11 23` ⇒ 会改变表内状态。

    正确用法：读用 `ReadBytes` + `Cjt188Value.DecodeBcd`（或通用原语 `MeterBcd`）； 写用 `Write(address, byte[])` + `Cjt188Value.EncodeBcd`。

    TryGetAddressSemantics(string, string, out DeviceAddressSemantics)

    【2026-10-23 新增】带数据类型提示的语义解析 —— 供「位/字双用途」地址使用 ✓。

    【为什么必须要它 ✗→✓ 实测缺陷】有些地址**同一串可以是位也可以是字**： * Modbus 裸数字 `800`：`ReadBool("800")` 读**线圈 800**、`ReadInt16("800")` 读**寄存器 800** —— 两个**完全不同**的区域 ✗ * ⇒ 只看地址串**无法**决定语义 ✗；必须由调用方告知"这个标签是什么类型" ✓

    ⚠️ **本仓 TFM 含 `netstandard2.0`，不支持 default interface method（实测 `CS8701`）** ✗ ⇒ 这是**抽象成员**，每个实现类都必须提供 ✓。 不涉及双用途地址的驱动，直接写 `=> TryGetAddressSemantics(address, out semantics);` 转调 ✓ （见 `MitsubishiMcDriver`）。

    【实测佐证】若不区分：`800 + int16` 建块得 `StartByte=50`（按**位号** 800/8/2 算）， 而正确应是 `StartByte=800`（**寄存器** 800）⇒ 读错位置 ✗。

    TryGetAddressSemantics(string, out DeviceAddressSemantics)

    CJ/T 188 的地址语义：每个 DI 是一个独立"区域单元"。

    🔴 为什么必须实现这个接口（收尾交叉测试探针实测）： CJ/T 188 的地址是 表地址;DI 或 DI，形如 901F / 911F / 00000000001234;901F。 这些**没有区域字母前缀**，通用解析器 PlcAddressHelper.TryParse **认不出**： 实测 901F=失败、911F=失败、表地址;901F=失败， 只有 8102 侥幸成功但被当成**数字 8102**（DataBlock='' ByteOffset=8102）✗

    ⇒ 建块层「画像不认的写法会解析失败 ⇒ 点位被排除 ⇒ **永远无值**」。 实测后果：3 个 DI 标签 ⇒ 建块只出 **1 块、1 个标签**，另 2 个被丢弃 ✗✗

    不实现它的替代方案为什么不行：仅靠 IsSingleValue=true（禁止合并） 只能避免"合并丢标签"，**但解析失败发生在合并之前** ⇒ 点位仍被排除 ✗

    语义设计：CJ/T 188 没有"寄存器地址"概念——每个 DI 就是一次完整应答。 因此把 **DI 本身当作 Area**（如 "901F"），Address 恒 0， BitsPerUnit = 8（按字节）。 每个 DI 一个区域 ⇒ 结构上不可能被合并（即使误传 allowMerge 也合不了）✓

    WriteCommandOnly(string)

    发一条"无载荷"写命令（表 16 中 L=03H 的命令：无载荷，只有 DI + SER）。

    为什么必须有这个专用方法（2026-11-03 交叉测试暴露）： 基类 NativeDriverBase.Write 对空数组一律拒绝 （ValidateWriteArray → "写入值不能为空数组"，P0 契约收口，既定决策不推翻）。 而标准表 16 里有三条命令**本来就没有载荷**：

    • A019H 出厂启用；
    • A101H 进入检定模式；
    • A102H 退出检定模式。

    ⇒ 走 WriteBytes 在**契约层就发不出去**（不是协议问题，是入口守卫）。 故提供本方法：它不经过 WriteBytes，直接组 L=03H 的写帧。

    ⚠️ 只有这三条命令该用它。其它写 DI 必须用 WriteBytes， 因为它会做长度校验与载荷编码。

    写机电同步数据/置表底数（控制码 16H，表 18）。
