    Interface IBitBatchReader

    支持「一次读取 N 个连续位」的驱动能力 ✓（位区专用 ✓）。

    ⚠️ **不要**用 ReadBytesAsync(string, ushort) 模拟本接口 ✗ —— 那条路的 `length` 是**字节** ✓，且本仓 MC 模拟器上位区字访问实测失败（`C0B0`）； 驱动错误信息提示并非所有 PLC 都如此 ⇒ **不可依赖**，位标签必须走位通道 ✓。

    未实现本接口的驱动 ⇒ 位标签只能逐点读 ✓（见 `DeviceRoot` 的兜底 ✓）。

    【2026-10-23 继承 IAddressSemantics ✓】位号/区域/位字属性本就是 地址语义的一部分 ⇒ 派生自通用语义接口 ✓，不再单独造一套 ✗ （否则批量位读与建块各用一套口径，必然漂移 ✗）。 §五 5.5。

    TryGetBitDevice(string, out string, out long)

    解析位地址 ⇒ 驱动口径的「软元件区域 + 位号」✓。

    【权威性 ✓】位号必须是**协议原生编号**（MC 的 `X20` = 0x20 = 32 ✓； 松下 `X100` = 160 ✓）；**不得**用通用地址解析器代算 ✗（进制/位字属性可能不同 ✗）。

    【区域一致性 ✓】areaKey 必须能区分**不同软元件** ✓ （如 `X`/`Y`/`M`；松下 `R`/`SM`）—— 一条读命令只能指定一个软元件码 ✗。 同一软元件的不同别名可以返回同一个 key ✓。

    ⚠️ 非位地址、解析失败、不支持 ⇒ 返回 false ✓（**不抛异常** ✓）。

    【实现方式 ✓】各驱动**不必**单独实现本方法 —— 用 TryGetBitDevice(IAddressSemantics, string, out string, out long) 从 TryGetAddressSemantics(string, out DeviceAddressSemantics) 派生 ✓（单一实现点 ✓）。 本签名保留是为了**不破坏既有调用方**（`BitBatchPlan`、`DeviceRoot` 探测等）✓。
