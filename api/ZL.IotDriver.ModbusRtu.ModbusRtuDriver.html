    Class ModbusRtuDriver

    Modbus RTU 串口驱动（基于 System.IO.Ports.SerialPort）。

    通过串口（RS-232/RS-485）与 Modbus RTU 从站通信，实现 IPlcDevice 接口。

    地址格式说明（五位数地址码）：

    • 00001～09999 — 线圈（功能码 01/05/15）
    • 10001～19999 — 离散输入（功能码 02）
    • 30001～39999 — 输入寄存器（功能码 04）
    • 40001～49999 — 保持寄存器（功能码 03/06/16）
    • 0～65535 — 直接使用原始地址，默认保持寄存器

    Converter

    当前字节序 —— 默认大端（与改动前逐字节一致 [OK]），子类可覆写。

    [!!] **【2026-10-28 框架修正，docs/506】原实现不可覆写，是真实限制** [X]： 原为 `private static readonly IEndianConverter _converter = BigEndianConverter.Default;` 且 `EndianConverter => _converter`（**无 virtual**）⇒ 子类**无法**改变字节序。 编译实验证实：子类写 `override IEndianConverter EndianConverter` 报 **`CS0506: not marked virtual, abstract, or override`** [X]

    **为什么必须修**：台达（Delta）串口协议按 HSL `DeltaSerial.cs:14,20` **明确要求 CDAB**，而我方 `delta-tcp` 也是 `CdabEndianConverter.Default`（`DeltaTcpDriver.cs:73`）⇒ 若串口版被迫用大端，会**与自家 TCP 版互相矛盾**，且 32 位跨寄存器数据 **静默错值** [X]（16 位值两种字节序结果相同 ⇒ 靠小值测试**发现不了** [X][X]）

    **零行为变更保证**：默认仍返回 ZL.IotDriver.ModbusRtu.ModbusRtuDriver.DefaultConverter（大端） ⇒ 现有 `XinJeSerialDriver` 与全部 RTU 场景**逐字节一致** [OK] 且 `EndianConverter` 属性签名未变 ⇒ 外部调用方零感知 [OK]

    IsAddressWritableOnThisChannel(string)

    本通道是否可写该地址（默认 true = 不改变任何既有行为）。

    成立前提：只在 ModbusRtuDriver 的**写入口**调用，当前共 4 处 （WriteBytesAsync / WriteAsync(string,bool) / WriteAsync(string,bool[]) / WriteHostOrderRegistersAsync）， 均在 WriteGate.Check 之后、ParseAddress 之前。 读路径不调用本方法 —— 否则会重犯台账 AX 的失败模式 （判据同时服务读写 ⇒ 连读一起打红）。

    [!!] **为什么需要**：ModbusRtuDriver 与 ModbusTcpDriver 是**两套独立实现**， 前者**没有** PreProcessWriteCommand（命令字节层改 FC）。 而汇川 AM 的 SM/SD 写**必须**改成官方 HMI 码 （SM=>0x35/0x3f、SD=>0x36/0x40） ⇒ 这类地址在串口上**无法正确写**（实测：SM10 得 FunctionWrite=15、与 QX10 同址 ⇒ 会写到**输出线圈**）⇒ 必须 **fail-closed**。

    [!] **适用边界**：基类恒返回 true，因此本守卫对"非 AM 汇川串口"的 所有 RTU 驱动均不改变行为；当前唯一返回 false 的覆写是 InovanceSerialDriver，且仅在 Series == AM 且地址为 SM*/SD* 时。
