    PlcMemoryLayoutCalculator

    PLC 点位物理内存布局计算器（单一事实源，docs/405 阶段二）。

    核心职责：统一计算一个 TagItem 在 PLC 底层物理内存中占用的**真实物理字节跨度**， 供块构建器（PlcReadBlockBuilder）、块定义（PlcReadBlock） 与值提取器（PlcValueExtractor）共同遵循，杜绝多处各写一套导致的尺寸失真。

    【四大物理不变量】 1. 定长类型：字节数由规范类型固定（如 short=2, int=4, double=8）； 2. 位地址（bool）：占用该位所在的 1 个字节； 3. 西门子 S7 STRING[M]：物理占用 = 业务容量 M + 2 字节前导头； 4. 西门子 S7 WSTRING[M]：物理占用 = 业务字数 M * 2 + 4 字节前导头； 5. Raw / byte[]：物理占用 = 声明字节数 M。

    PlcReadBlock

    PLC 批量读取块。 在工业现场，逐标签读取 PLC 数据会导致大量网络往返，严重影响采集效率。 PlcReadBlockBuilder 会将地址相邻的标签合并为一个读取块， 一次网络请求读取连续字节区域，再由 PlcValueExtractor 从 buffer 中提取各标签值。

    PlcReadBlockBuilder

    智能读取块合并构建器。

    核心职责：将大量散落的标签地址，按"地址相邻、同数据区"的原则合并为少量 PlcReadBlock。 工业现场的 PLC 通常有 PDU 大小限制（如西门子 S7-1200 为 240 字节）， 合并策略需要在"减少网络往返次数"和"不超出 PDU 限制"之间取得平衡。

    三个关键参数控制合并行为：

    • maxGap：两个标签间允许的最大字节空隙（空隙内无有效数据但仍需读取）
    • maxBlockSize：单个读取块的最大字节长度（不能超过 PLC 的 PDU 限制）
    • minEfficiencyPercent：最小有效数据占比（避免"读 200 字节只要 2 字节有用"的低效合并）

    PlcValueExtractor

    从批量读取的 buffer 中提取各标签的实际值。

    工作流：BatchEngine 一次性读取 PlcReadBlock 对应的连续字节区域到 buffer， 然后由本类遍历块内每个标签，根据其地址偏移和数据类型， 利用 IEndianConverter 进行字节序转换，得到 .NET 强类型值。

    关键设计：IEndianConverter 封装了大小端（Endian）差异， 西门子 S7 是大端（Big-Endian），Modbus RTU 也是大端， 但某些国产 PLC（如汇川）可能使用小端，通过注入不同的 EndianConverter 即可适配。
