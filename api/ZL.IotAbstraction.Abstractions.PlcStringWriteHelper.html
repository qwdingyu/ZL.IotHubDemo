    MaxS7WStringLength

    西门子 S7 WSTRING 前导头能表达的容量上限（Byte0-1 是 16 位「字」 ⇒ 65535）。

    【为什么必须是硬上限】头字段只写 16 位 ⇒ 超过即**静默回绕** ✗： 实测 maxChars = 65536 ⇒ 头声明容量变成 **0**（PLC 视为 WSTRING[0]）； maxChars = 100000 ⇒ 变成 34464 ✓，且 payload 会被分配成 100000*2+4 = 200004 字节 ⇒ **把 128KB+ 写到字段之外** ✗（灾难）。

    BuildS7StringPayload(string, Encoding, int)

    构造西门子 S7 STRING 的完整写入负载（两字节前导头 + 内容）。

    S7 STRING 布局：字节 0 = 最大长度，字节 1 = 实际长度，其后为内容。 传入的 maxLength 为点表配置的字符串最大**字节数** （西门子 STRING[n] 的 n 就是字节数；本仓读侧 ReadString(addr,size) 走 ReadBytes(addr,size)、 写侧短则补零到该长度，两侧同口径 —— 原文写“最大字符数”是用词不准， 更正）； 实际写入长度取 min(内容字节数, maxLength)，不足部分自动补 0x00。

    GetRawPayloadOverCapacityMessage(int, int)

    显式容量（maxLength > 0）下 Raw 负载是否超长：超长返回可直接回报的错误消息， 未超长（含未配置容量）返回 null。

    【为什么必须有这一步】BuildRawPayload(string, Encoding, int) 的契约是 “不截断超长，由调用方决定 Fail 或截断”（见该方法注释）；而 Raw 写入路径原先四处 （NativeDriverBase.WriteString/WriteStringAsync、SiemensS7Driver.WriteString/WriteStringAsync 的 Raw 分支）都没有做这个判定。同时 NormalWriteRequest.StringLength、 SafetyWriteRequest.StringLength 对外文档写的是“字符串最大长度（字节/字符）”， 且 tag.Length 就是字段字节宽（读侧 ReadString(addr, size) 走 ReadBytes(addr, size)；写侧短则补零到该长度）⇒ 超长时会写穿点表 Length 界定的字段， 静默覆盖其后相邻的 PLC 存储区。 兄弟路径 S7 STRING / WSTRING 一直是超长即 Fail（SiemensS7Driver.WriteS7String/WriteS7WString） ⇒ 本方法把同一约定补齐到 Raw 路径，并做到“一处定义、四处复用”，避免阈值与提示语各自漂移。

    TryBuildS7SmartStringPayload(string, Encoding, int, out byte[], out string)

    构造西门子 S7 WSTRING 的完整写入负载（4 字节前导头 + 大端字符数据 ✓）。

    S7 WSTRING 布局：字节 0-1 = 最大长度（字，大端序），字节 2-3 = 实际长度（字，大端序）， 其后为每字符 2 字节的 **大端**字符数据（逐 16 位字交换 ✓）。每字=1 个 UTF-16 编码单元，因此： 内容总字符数超出 maxChars 时按 maxChars 截断；不足则补 0x00 到 maxChars*2。

    点表配置的最大字符数（= PLC DB 中 WString[n] 的 n）。<=0 时按实际字符数回退 min(127, max(实际字符, 20))。超长截断以避免写越界。
