    Class PlcFleetManager

    PLC 集群管理器 —— 多 PLC 场景下的启动编排与运行时协调中枢。

    【设计意图】 当系统需要同时管理 30-40 台 PLC 时，简单的"逐个 new 出来"会导致：

    1. ThreadPool 饥饿：40×8=320 个 Task 同时竞争默认 16 线程
    2. SYN 风暴：40 个 TCP 连接同时发起
    3. 无启动状态可见性：不知道哪些 PLC 启动成功、哪些失败

    PlcFleetManager 解决这三个问题：

    • 启动前预热 ThreadPool（消除饥饿）
    • 分批启动 PLC（消除 SYN 风暴，通过 PlcConnectionThrottle）
    • 提供启动状态报告（可观测性）

    【使用方式】 在应用启动入口（Program.cs / Service 入口）调用： PlcFleetManager.Initialize(estimatedPlcCount: 40); 然后在创建 PLC 实例时通过 RegisterDevice 注册。

    Shutdown()

    优雅关闭集群管理器：停止背压监控器，并完整还原单例状态以便再次 Initialize(int, int, int, int?)。

    【为什么要还原状态 —— 2026-10-11 审查发现并修复】 原实现只 Dispose 监控器，**不置空 _instance、不清 _isInitialized**， 实测（探针三步）： ① 首次 Initialize(1) → 有"初始化完成"日志、IsInitialized=True； ② Shutdown() 之后 → IsInitialized **仍为 True**（状态不诚实）； ③ 再次 Initialize(1) → 日志 **0 条**，被 if (_isInitialized) return; **静默跳过，完全没有重新初始化**。

    【因此造成的实际危害】 · "先 Shutdown 再 Initialize"（宿主重启集群 / 重配 PLC 数量）会**静默失败**： 背压监控不会重建、连接限流仍是旧参数，而调用方**收不到任何提示**； · DriverFactory 用 GetStatus().IsInitialized 判断是否提醒调用方 "尚未 Initialize，多 PLC 场景请先初始化"（见 DriverFactory 的告警分支）—— Shutdown 后该值仍为 True ⇒ **该警告不会再出现**，运维失去唯一的提示信号； · PlcHealthCheck 上报的集群状态同样失真。

    【刻意不还原的部分】ThreadPool.SetMinThreads 属**进程级**调优， 还原可能破坏其它组件的线程供给；且它只是"下限"，调大本身无副作用。 连接限流器由下一次 Initialize(int, int, int, int?) 重新配置（PlcConnectionThrottle.Initialize）。

    【并发】整个还原过程在 ZL.IotEngine.Runtime.PlcFleetManager._initLock 内完成，避免与 Initialize(int, int, int, int?) 竞争。 重复调用本方法是安全的（第二次直接返回）。
