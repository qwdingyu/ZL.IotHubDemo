    KeyenceMcDriver

    基恩士 MC 协议驱动。基于三菱 MC 协议，基恩士 KV-7500/5500 等系列使用。 地址格式：MR0, LR0, CR0（基恩士专用的继电器/寄存器类型）。

    **MR / LR / CR / CM 已实现** ✓（2026-10-21，依 HSL 12.9.2 `ParseKeyenceFrom` + 码值表）。 `MR/LR/CR` 的编号是**复杂地址**（2026-10-23 修正 ✗→✓）：无点号且长度 > 2 时 按 `前段 × 16 + 末两位十进制`（如 `MR100` ⇒ **16**，不是 100 ✗）；带点号时 按 HSL `CalculateComplexAddress` 处理末段（含 A-F 用 16 进制）✓。

    ⚠️ **可信度边界**：码值与复杂地址语义均来自 HSL 12.9.2 反编译，**未经真机验证** ⇒ 对外只能标“依 HSL 实现”，不得声称“已验证” ✗。详见 ParseAddress(string) 内注释。

    ⚠️⚠️ **必须知道的使用陷阱（2026-11-10 全局审查补充）**： 除 ZR / MR / LR / CR / CM 外，**其余前缀一律走 `fallback` = 三菱 MC 的解析器** ⇒ 按**三菱区域码**下发 ✗

    **为什么是这样**（不是缺陷，是参考实现如此）：HSL 的 KeyenceMcNet : MelsecMcNet **直接继承**，只对布尔地址做额外判定，其余完全复用三菱解析 ✓ ⇒ 我方 `ParseKeyenceAddressCore(address, fallback)` 与该语义一致 ✓

    **后果**：`SM100` / `SD100` / `X100` 这类在**三菱**里合法的写法， 本驱动**不会报错**，而是按三菱区域码发出去 ⇒ 若目标基恩士 PLC 上该区不存在或含义不同 ⇒ 可能**读到错误的区，且 `IsSuccess = true`** ✗✗ ⇒ **点表请只用 `MR` / `LR` / `CR` / `CM` / `ZR`**； 确需其它区时，**先对照基恩士手册确认区域码与三菱一致**后再用 ✓

    MitsubishiMcDriver

    三菱 MC 协议驱动 —— 纯 C# 实现，不依赖任何第三方库。28 个前缀（与 melsec-mc 白名单一一对应，2026-10-21 实测 28/28 通过 ✓）： D M W X Y L B F V S R Z SM SD SW SB SS SC ZR TN CN CC CS TS TC DX DY SN。不含裸 T：定时器须写 TN(当前值)/TS(触点)/TC(线圈)，与 HSL 一致（MelsecMcDataType.cs/112/117 只有 TN/TS/TC）。含 SN（2026-10-21 已修）： 原 Format=100 是非法进制（.NET 只认 2/8/10/16）⇒ 任何 SN 地址都抛 ArgumentException: Invalid Base. ✗； 现按 HSL MelsecMcDataType 的 FromBase=10 修正 ⇒ SN100 正常 ✓（case 内已注明）。 【进制】以 HSL MelsecMcDataType.FromBase 为准（逐区实测）：16 进制 = X Y B W SW SB DX DY；其余为 10 进制， 含 ZR（2026-11-18 Owner 裁定：按官方 SH-080008 用 16 进制）。【A-1E】X/Y 为 8 进制，M/S/D/R 为 10 进制。

    PanasonicMcDriver

    松下 MC 协议驱动。基于三菱 MC 协议，松下 FP 系列使用。 地址格式：R0（内部继电器）、X0（输入）、Y0（输出）、D0（数据寄存器）、L0（链接继电器）、W0/DT0（报警/数据）。 默认端口：6010（历史默认，无官方依据）。

    ⚠️ 官方 FP7 Ethernet Expansion 手册 §9.1.2 明确 MC 协议 Home port number 5000 (Recommended)；6010 在本仓未找到任何官方原文支撑。 为不破坏既有现场点表/直连代码，**保留 6010 为默认值**，但不再声称“松下标准”； 新项目建议显式配置 5000（或按设备实际监听端口）。
