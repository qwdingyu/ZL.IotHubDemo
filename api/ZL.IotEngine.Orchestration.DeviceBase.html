    Class DeviceBase

    简化版设备基类 —— 工控 PLC 数据采集的「轻量驱动骨架」。

    与 DevicePro（高级版，含 QoS 写入队列、ConnectionStateManager）不同， 本类面向中小型采集场景：直接同步读写 PLC 寄存器，不使用写入队列和连接状态机。

    核心职责： 1. 连接生命周期管理（初次连接 + 断线指数退避重连） 2. 多频率后台扫描引擎（按标签组 ScanRate 分波次轮询 PLC） 3. 心跳写入（独立锁，不阻塞业务读取） 4. 按数据类型分发同步/异步读写 5. 资源释放（Dispose 模式）

    继承链：DeviceBase → DeviceRoot（标签管理/计划构建/事件发布）→ object 实现接口：IDeviceDriver（驱动契约）、IPlcDriver（PLC 读写契约）、IDisposable

    DeviceBase(DeviceConfig, bool)

    构造函数 —— 初始化设备并启动后台任务。

    执行顺序： 1. 调用 Initialize() 解析配置、初始化标签字典 2. 若初始化成功，异步发起首次连接（不阻塞构造函数） 3. 启动后台任务（重连循环、批量读取循环、心跳循环、Ping 探测）

    startFirstConnectInCtor：首连是否由基类构造启动。 ManagedDeviceBase 注入式壳必须传 false 并在自身构造体 （驱动注入赋值完成）之后调用 StartFirstConnect() —— C# 语言限制基类 ctor 必先于派生构造体执行，若由基类在 ctor 内 Task.Run 首连， 池线程压力下首连可能抢在派生赋值前读到的仍是「未注入」状态， 走进 lazy 分支自建第二个驱动（+1 泄漏，详见 ManagedDeviceBase 注入构造注释）。

    _firstConnectTask

    构造函数发起的首次连接任务句柄。

    【为什么要持有引用】首次连接是后台 fire-and-forget 任务，若不持有引用： 1. Dispose 无法等待它退出，可能在它仍持有/即将释放 connectLock 时就 Dispose 掉信号量， 导致 connectLock.Release() 抛 ObjectDisposedException（落入 UnobservedTaskException，运维不可见）； 2. 任务脱离 globalCts，Dispose 后仍可能继续访问已释放资源。 持有句柄 + 使用 globalCts.Token，使其纳入统一的优雅停止流程。

    protected：派生类（ManagedDeviceBase）需在自身构造体完成后补设首连句柄 （注入式壳在驱动赋值就位后才允许启动首连，见 StartFirstConnect 注释）。

    Overrun

    单频率扫描引擎循环 —— 按指定频率周期性执行一次批量读取。

    v12 优化：改用 CustomPeriodicTimer 替代 Task.Delay。 原因（T8 测试实测数据）：

    • Task.Delay 版本：实际周期 = IO耗时 + scanRate，长期累积漂移。 T8 实测 100ms 目标下 30s 漂移 403ms，1小时漂移超过 800ms。
    • PeriodicTimer 版本：以绝对时间为基准，自动补偿 IO 耗时。 T8 实测 100ms 目标下 30s 仅漂移 8ms，精度提升 50×。

    工控行业标准（对标 Kepware）：采集周期必须基于绝对时间，不受 IO 耗时影响。

    异常处理：捕获后短暂等待（min(scanRate, 1000)ms），防止持续异常导致 CPU 飙升。 PeriodicTimer 不提供内建错误退避，需手动控制。

    BatchReadLoop(CancellationToken)

    批量读取主循环 —— 多频率自适应轮询引擎（波次监管者）。

    工控场景中不同标签对实时性要求不同： - 关键工艺参数（如温度、压力）需要 100ms 级采集频率 - 辅助状态（如计数器、产量）可接受 1-5 秒级频率 本方法为 `scannablePlans` 里的**每一个频率桶**维持一个独立扫描波次（Task.Run）， 各自按自身周期运行、互不干扰；并在运行期**持续对齐**桶集合与波次集合 （`BuildPlan()` 会整体替换 `scannablePlans`，桶键集合随之变化 —— 详见方法内注释）。

    [!] 历史说明：v12 之前「所有标签都用默认频率时回退为单循环（Task.Delay + ExecutePlanByRate(0)）」 的分支已删除 —— `BuildPlan` 恒为每个块分配桶键（默认频率桶的键 = `plcTriggerInterval`）， 因此该分支只在"计划完全为空"时可达，而那时它与监管循环一样只是空转， 保留它反而多一条"同一语义两处实现"的分叉来源（docs/271 / 273 / 275 / 279 的病根）。

    ClearSnapshotOnDispose()

    释放设备资源（同步，Best-Effort）—— 停止后台任务、关闭 PLC 连接、释放锁。

    释放顺序（重要）： 1. 发送取消信号（globalCts.Cancel）—— 通知所有后台循环退出 2. 等待后台任务优雅退出（最多 1.5 秒）—— 给正在进行的 PLC 读写留完成时间 3. 释放 CancellationTokenSource 4. 关闭 PLC 连接（释放 Socket/TCP 资源） 5. 释放所有 SemaphoreSlim 锁

    这是工控程序的标准 Dispose 模式，确保程序退出时不会遗留未关闭的 PLC 连接， 避免 PLC 侧连接数耗尽（许多 PLC 有最大连接数限制，如西门子 S7-1200 最多 16 个）。

    【注意】此方法使用 .Wait() 同步等待，会短暂阻塞线程池线程。 如需非阻塞释放，请使用 DisposeAsync()。

    HalfOpenProbeAsync(CancellationToken)

    Circuit Breaker 半开探测 —— 重连后验证 PLC 是否真正可用。

    TCP Socket 连通 ≠ PLC 程序正常运行。某些 PLC 在固件崩溃或程序停止时 仍能接受 TCP 连接但无法响应 S7 协议请求。此方法通过实际读取一个标签 来确认 PLC 端到端可用。

    探测策略（优先级从高到低）： 1. 心跳标签（通常是最小 bool 类型，读取最快） 2. 就绪信号标签 3. 任意一个启用的采集标签

    [!!] 2026-10-31 收敛改造（单一真源）：旧实现自写一份探测（ReadValue 透传原始地址、 **不持 deviceLock**——触发 ReadValue 的"未持锁"警告、且并发读取无锁纪律； 位标签不走位通道、非字符串无 Length 钳位）。现**委派 DeviceRoot.ProbeTagAsync** （隔离区拆探沿用的硬化原语）：位标签自动走 IBitBatchReader 位通道 （MC 位区字访问实测失败，docs/452）、读取全程持 deviceLock、Length 超限钳位并记日志 （PlcReadLengthGuard，docs/391）。该原语已被隔离区路径在本类上生产验证 [OK]

    HeartBeatLoop(CancellationToken)

    心跳写入循环 —— 后台常驻任务。

    工业场景中的作用：周期性向 PLC 写入心跳值（0/1 交替）， 用于 PLC 程序判断上位机通讯是否正常。PLC 侧通常有看门狗逻辑： 若心跳值长时间不变化，则判定上位机掉线，触发安全停机或报警。

    心跳写入经过 deviceLock 保护（S7 单连接要求串行访问）， 所有心跳写入带 5 秒超时保护，防止 PLC 无响应时锁被永久持有。
