    Class DeviceWriteDispatch

    把"按运行时类型分发到对应的类型化写入"这条规则收敛到一处。

    【为什么异步能共享、同步不能】 IPlcDevice **声明了异步的类型化写入**（WriteAsync(string, bool/short/…/double)、 数组版、WriteAsync(string, string, Encoding)、WriteBytesAsync） ⇒ 分发可以**经接口**完成 ⇒ 能共享 [OK]； 而**同步**的类型化写入**不在**接口里（只有 Write(string, object|string|byte[])） ⇒ 无法经接口分派，给公开接口补成员又是**破坏性变更** ⇒ 同步分发**消不掉** [OK]。

    【本实现覆盖的变体】对应原 AllenBradleyCipDriver / ModbusRtuDriver 两份 **逐字相同**的实现：11 个分支（bool/short/ushort/int/uint/long/ulong/float/double/string/byte[]）， 字符串固定用传入的编码（原为 System.Text.Encoding.UTF8），不支持的类型返回 Fail("不支持的类型: …")。

    【不覆盖的变体（有意）】SiemensS7Driver 多一支 byte 且有 null 检查； MitsubishiMcDriver/OmronFinsDriver 是 Task.Run(() => Write(address, value)) **一行转发到同步路径**（不是同一条规则）；NativeDriverBase/SerialDriverBase/ ModbusAsciiDriver/HttpDriverBase 各自不同 ⇒ 合并它们需要**统一语义**， 属产品决策，已在列出完整变体地图 [OK]。
