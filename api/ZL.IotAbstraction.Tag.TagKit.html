    BuildTagDictionary(IEnumerable<TagItem>)

    由标签集合构建点表字典（统一比较器 + Id 归一化 + 保留首个）。

    【为什么需要】内存注入路径（DeviceConfig["Tags"] 传 IEnumerable<TagItem>）此前直接 list.ToDictionary(t => t.Id)：

    • Id 带首尾空白时不 Trim，与文件加载路径语义不一致；
    • 存在重复 Id（含仅大小写不同）时 直接抛 ArgumentException， 设备初始化整体失败 —— 而文件加载路径是"保留首个 + 跳过"。

    统一走本方法后，内存注入与文件加载两条路径语义一致。

    【刻意不过滤 Enable】文件加载路径会跳过 Enable=false 的行， 而注入路径历史上不跳过。本次只统一"比较器 / 空白 / 重复键"三项语义， 不改变"哪些标签进入字典"的既有行为 —— 静默丢弃调用方注入的标签， 正是本项目反复出现的"点位采不到值"类事故。该差异另行评估，不在本次范围。

    LoadTags(string, out TagLoadDiagnostic)

    【2026-11-09 新增， / A-234】带诊断的点表加载 —— 把"为什么 0 条"讲清楚 ✓

    🔴 **为什么需要（本仓真实缺陷，务必保留说明）**： LoadTags(string) 在**任何**失败情形下都**静默返回空字典** ✗ —— 于是 `DeviceRoot` 打一句"警告"后**照常** `_isInitialized = true` 并打印 「**初始化成功，加载了 0 个标签**」✗✗。 ⇒ 现场表现：程序正常启动、`Connect()` 返回 `true`、**所有点位读 `false`/`0`** ⇒ **报警不触发** ✗✗✗

    ✅ **本重载不改 LoadTags(string) 的任何行为**（纯增量 ✓）， 只是**额外**区分五种情形，让调用方能"按情形处理"而不是"一律当成功"：

    • Loaded —— 正常，`LoadedCount > 0` ✓
    • FileNotFound —— **路径给了却找不到文件** ⇒ 🔴 **配置错** ✗
    • FileEmpty —— 文件存在但**零字节** ⇒ 多半是部署漏了 ⚠️
    • NoValidRows —— 🔴 **文件有内容却解析出 0 条** ⇒ **最危险的一类**：XML 元素名写成 `<Tag>`（须 `<TagItem>`）、 或全部 `Enable="false"`、或只有表头没有数据行 ⇒ / A-237 ✗✗
      ⚠️ **2026-11-10 更正**：原文把"漏写 `Enable`"也列为成因（当时 XML 缺省为 false）✗ 三格式已统一为 `true`（`TagItem.DefaultEnable`）⇒ 漏写**不再**导致 0 条 ✗
    • Malformed —— 解析抛异常（XML/JSON 语法错）✗
