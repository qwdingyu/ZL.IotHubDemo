    Remarks

    一、HSL 有没有 BACnet 规范？—— 没有（已实测，不是推断）

    • grep -rli "bacnet" _vendor/hsl-decompile-13.0.3 | wc -l ⇒ **0**（该目录 100 个子目录全扫）
    • 复核命令（可直接跑）：grep -rli bacnet /Users/dingyuwang/0-X/ZL.PlcBase/_vendor/hsl-decompile-13.0.3 | head
    • ⇒ HSL **不提供** BACnet 驱动、也就没有"HSL 地址惯例"可对齐 ⇒ 按 ASHRAE 135 的对象/属性模型自定，并本文档化。

    二、BACnet 标准本身怎么寻址（ASHRAE 135）

    标准**没有"地址字符串"**这个概念，点位恒由四元组定位：

    ( objectIdentifier = { objectType, instance } , propertyIdentifier , arrayIndex? , priority? )
例：{ analogValue, 1 } + presentValue          → 读/写该点当前值
    { analogValue, 1 } + priorityArray + 8     → 读第 8 号命令优先级槽

    device 不是"地址的一部分"，它是**另一台对象**（objectType=8）的实例号； 但 BACnet/IP 上必须先知道"问哪台设备"，故实际工具都把 device 与点位一起表达。

    三、行业工具怎么表达（本地可查的三处证据）

    来源表达形式
    BACpypes3 / BAC0（本次交叉裁判）"analogInput,1" + 属性名 "presentValue"；device 另给 "device,1234" （实测见 docs/drivers/Bacnet.md §9）
    PLC4X BacNetIpTag字段就是 deviceIdentifier / objectType / objectInstance（**四元组一致**）， 但其地址字符串正则仍写着 "TODO: finish me..." ⇒ **无可抄的字符串标准**
    YABE / BACnet-stack 工具type,instance + 属性名（与 BACpypes 同形）

    四、本驱动为什么定成现在这个形式

    <device>.<AI|AO|AV|BI|BO|BV|MSI|MSO|MSV|DEV>:<实例>.<PV|PA|RD|NAME|DESC|UNITS|TYPE|OID>[.索引/优先级]
1001.AV:1.PV      → device 1001 / analogValue 1 / presentValue
1001.AV:1.PV.8    → 同上，写命令优先级 8
1001.AV:1.PA.8    → priorityArray 第 8 槽（只读）
    1. device 放第一段：采集配置里"一个连接一台设备"，地址带 device 便于 多设备共库、日志定位、以及**与设备侧校验**（device 不符 ⇒ 对端回 unknown-object；我方仿真器就是按 inst != _deviceId 判的）。
    2. 对象用 TYPE:instance：与 ASHRAE 的 objectIdentifier 一一对应， 也与 BACpypes 的 "analogInput,1" 同构（只是分隔符 : 换成 ,，避免与三段点号混淆）。
    3. 属性用标准缩写：PV/PA/RD/NAME/DESC/UNITS/TYPE/OID 分别是 85/87/104/77/28/117/79/75；缩写只是书写便利，落到线上仍是标准属性号。
    4. 第四段语义随属性而变（唯一"非对称"设计）：PA 后是**数组索引**、 PV 后是**写优先级** —— 因为 BACnet 的 priorityArray 是数组、 而 presentValue 的写入才会带 priority。这条最易错，已用 2 条用例 + 变异自证钉住 （见 tests/ZL.IotHub.Tests/Drivers/BacnetAddressTests.cs）。

    五、与标准写法的对照（便于与现场/第三方文档对齐）

    本驱动等价的 BACpypes3 写法
    1001.AV:1.PVread_property(dev1001, "analogValue,1", "presentValue")
    1001.AV:1.PA.8read_property(dev1001, "analogValue,1", "priorityArray", 8)
    1001.BV:3.PVread_property(dev1001, "binaryValue,3", "presentValue")（ENUMERATED 0/1）
    1001.MSV:4.PVread_property(dev1001, "multiStateValue,4", "presentValue")（UNSIGNED）

    六、为什么不照抄 BACpypes 的 "analogInput,1"

    它的字符串里**不含 device**、且属性是**第二参数**（不是字符串的一部分）⇒ 落到"单字符串地址"的驱动契约里，必须再造一层参数，配置侧也更难表达"哪台设备"。 故本驱动把 device 与属性都并入单字符串，**语义与标准一一对应、书写更省**。
