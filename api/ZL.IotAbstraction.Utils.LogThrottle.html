    Class LogThrottle

    日志时间节流：同一 key 在 DefaultInterval 内最多放行一次。

    【为什么要有这个类 —— 2026-10-17 全局复盘】 本仓此前"日志刷屏"的治理是**各写各的**：DeviceRoot 用内联的 _lastHealthLogTicks（周期健康日志 60s）、DriverFactory 用 volatile 的 "只发一次"标志、而失败路径（Ping 告警/块读超时/块读异常）**什么都没用** ⇒ 按周期刷屏。 第一次修复时我把同一段节流逻辑**复制到了两个类**里 —— 那正是本仓反复出问题的形态 ⇒ 复盘后收敛为**本类唯一实现**。

    【设计取舍】 · **无锁**：极端并发下最多多打一条（日志重复无害），换取采集热路径零锁竞争 —— 与 DriverFactory 的"重复警告无害"取舍一致； · **键的基数有限**（块地址 / 固定名）⇒ 内存有界，无需淘汰； · 间隔是**类级默认值**（不是每个实例各一个旋钮）⇒ 全仓只有一个口径，避免"两处阈值不一致"。
