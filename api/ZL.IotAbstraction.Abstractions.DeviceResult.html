    FailureTag

    可扩展失败标签（2026-11-03 新增，可空）。

    🔴 为什么用 string 而不是再加枚举值： Azure 的 ResponseError.Code、K8s 的 Status.Reason 都是 string ⇒ 服务端/厂商可自由扩展，**不必每加一个新错误就改公共 API** ✓

    用途：承载品牌/厂商自定义细分，命名建议 <品牌>.<域>.<原因>， 如 "Inovance.SM.NotWritable" ✓

    ⚠️ 不得用它替代 Kind —— Kind 是跨协议统一维度， 本字段只是厂商扩展通道 ✓

    Kind

    失败性质（2026-11-03 新增，跨协议统一）。成功时恒为 Unspecified。

    🔴 与 ErrorCode 的区别： `ErrorCode` 是**厂商/协议自有码**（如 Modbus 异常码 2）； `Kind` 是**跨协议统一的失败性质**（地址错/未连接/超时…）⇒ 下游据此做程序化分支 ✓

    ⚠️ 未显式指定时为 Unspecified， 由 FailureClassifier 从 `Message` **尽力推断**（覆盖约 63%，见该类注释）✓
