    Class DeviceRoot

    设备采集根类 —— 整个 PlcBase 库的「采集引擎核心」。

    在工控 SCADA/MES 集成场景中，本类承担以下关键职责： 1. 标签管理：从配置文件或内存字典加载 PLC 点位标签（Tag），按用途分为监控标签(M)、心跳标签(HB)、就绪标签(RO)。 2. 采集计划构建：将分散的标签地址合并为连续的「读取块」(PlcReadBlock)，减少 PLC 通讯往返次数，提升吞吐量。 3. 批量读取调度：按扫描频率(ScanRate)分组执行读取计划，支持自适应间隔调整（快设备快采、慢设备慢采）。 4. 质量管理与坏点隔离：连续读取失败的通讯块会被拆解为单点探测，坏点地址自动隔离，定时自愈。 5. 变更检测与事件发布：对比本地缓存，仅当值变化超过死区(Deadband)时才触发 DataChange 事件，降低下游压力。

    子类（如 DevicePro、DeviceBase）通过实现抽象方法来适配具体的 PLC 协议（西门子 S7、Modbus TCP、汇川等）。

    QuarantineTags

    工业现场常见问题：PLC 程序修改后某个地址被删除或类型变更， 但该地址仍在采集配置中，导致整个通讯块读取失败（"一颗老鼠屎坏了一锅汤"）。 隔离机制将坏点从批量读取计划中剔除，保证其他正常地址不受影响。

    Start()

    统一启动入口。用于"后置添加标签"模式 —— 构造时 Tags 未就绪（来自 config 的 InjectTags 或 TagFilePath 均为空）， 在外部添加 Tags 完成后调用此方法完成初始化并启动所有后台任务。

    幂等安全：可多次调用，不会重复启动已在运行的任务。

    调用顺序：

    1. Initialize() — 重新初始化标签字典（config无Tags时不覆盖现有Tags）
    2. BuildPlan() — 使用当前Tags重建采集计划（lock 保护）
    3. StartBackgroundTasks() — 启动/检查所有根类后台任务
    4. StartSelfBackgroundTasks() — 启动/检查子类专属后台任务

    典型用法： 

    var driver = new HslUnifiedDriver(config);
driver.Tags.TryAdd("TAG_0", new TagItem { ... });
driver.Tags.TryAdd("HB1", new TagItem { Id = "HB1", TagType = "HB", ... });
driver.Start();  // 一键启动，替代手动调用 Initialize/BuildPlan/StartBackgroundTasks

    StartBackgroundTasks()

    启动所有后台任务（重连、读取、心跳、Ping 检测、隔离区自愈）。

    每个任务都有防重入保护：只在任务未启动或已完成时才创建新任务。 所有任务共享 globalCts 取消令牌，支持统一优雅停止。

    子类专属的后台任务启动入口。 继承体系中的模板方法模式（Template Method）：

    Stop()

    暂停采集（docs/600 P2-23）：五个后台循环退出，但连接保持、实例可再次 Start()。

    [!!] **原实现没有此能力** [X] —— 现场"检修/换型/临时下线"想暂停采集，**只能 `Dispose()`**， 而 `Dispose` **不可恢复** ⇒ 必须重建实例（撞 P0-7/P0-8/P2-22）[X]

    [!] 与 `Dispose()` 的区别：

    • `Stop()` —— 取消 `_pauseCts` ⇒ 循环退出 [OK]；**连接保持** [OK]；**可 `Start()` 恢复** [OK]
    • `Dispose()` —— 取消 `globalCts` ⇒ 循环退出 ＋ **释放连接** ＋ **不可恢复** [X]
