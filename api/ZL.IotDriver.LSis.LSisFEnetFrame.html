    Class LSisFEnetFrame

    FEnet 帧的构造与解析 [OK]（纯函数 [OK]，不碰 socket [X] ⇒ 可在 CI 门禁内离线单测 [OK]）。

    【为什么单独成层】把"帧长什么样"与"怎么收发"分开 [OK]： 纯函数部分可在门禁内被测死 [OK]，驱动只剩薄薄的 IO 包装 [OK]。

    [!!] **【协议基准在此】完整协议详录见 `docs/429_LSis_FEnet协议详录_源码与实测全量对照`** [OK] —— 其中 §一 是帧结构、§三 是 `dt` 与 `length` 口径、§四 是字节序 [OK]。 [!] **改动前必读** [X]：本项目在 LSis 上反复推翻多次，根因都是"把源码当成对端行为"[X]， 现在固定的判据顺序是 **① 先抓包 → ② 再看数据落点 → ③ 最后才看源码** [OK]（见 `docs/429` §七 [OK]）。

    【唯一权威来源 [OK]】每条布局均逐条核对自 **vendor 的 HSL 12.9.2** （`_vendor/.../LSIS/LSFastEnet.cs` [OK]），并与仿真器侧的**抓包实测**互相印证 [OK]：

    • PackCommandWithHeader —— 20 字节头（含长度与校验和 [OK]）
    • BuildReadByteCommand / BuildWriteByteCommand —— 批量读写 [OK]
    • BuildReadIndividualCommand —— 位读（**结构不同** [X]）
    • ExtractActualData —— 响应解析 [OK]

    [!] 不得据 NuGet DLL 的运行时行为反推 [X]（两者在 MX 上不同 [X]，见 docs/425 §4 坑 C [OK]）。

    Remarks

    布局（逐字段 [OK]）：

    [0..7]   "LSIS-XGT" [OK]
[8..11]  0 [OK]
[12]     CPU 类型 [OK]
[13]     51 [OK]（固定 [OK]）
