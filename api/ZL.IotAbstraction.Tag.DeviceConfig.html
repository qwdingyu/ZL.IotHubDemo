    Class DeviceConfig

    通用设备配置容器。

    使用 Dictionary 灵活存储任意键值对配置参数（IP、端口、标签路径、扫描间隔等）， 支持从 JSON 文件、数据库或上层应用动态构造后注入到 DeviceRoot/DevicePro。

    线程安全说明：本类本身不是线程安全的，应在设备构造阶段（单线程）完成所有配置写入， 运行时仅做只读访问。如需热更新配置，由调用方负责加锁。

    RequireTags

    【2026-11-09 新增，唯一权威口径】本设备必须有点位才允许连接（默认 false）。

    🔒 **这是【策略】开关，不是【机制】** —— 两者的分工由钉死：

    • **机制（引擎自动，无开关）**：`TagsFailedToLoad`（**配了点表却加载失败**＝确定错误） ⇒ `Connect()` **一律拒绝** ✓
    • **策略（应用显式）**：RequireTags = true ⇒ 额外把「当前 0 个点位」也视为错误 ✓

    ⚠️ **为什么默认 false**（架构决定，非"怕改测试"）✗： ① 库**无法知道**用户意图（协议自测？地址级 I/O？后置加点？采集？）⇒ 不该替用户决定 ✗ ② 仓库 `DeviceRoot.Start()` 的 XML 注释**明文档支持**"构造时 0 点位（后置添加标签）" ⇒ 默认 `true` 等于**推翻该契约** ✗ ③ 与「点表默认只读」不冲突：那条管**权限**（安全侧收紧），本条管**校验强度**（默认不误伤）✓

    ✅ **生产采集部署建议**：由宿主显式设 RequireTags = true ⇒ 把"忘了配点表"从"静默采不到"变成**连接即失败** ✓

    ⚠️ 命名刻意用**正向**表述（"需要点位"）而非 `AllowEmptyTags`（"允许空"）—— 正向命名让默认值 false 自然合理，避免读代码时的双重否定 ✓

    GetWarnedBadConfigValues()

    【A-260】查询"本次进程内有哪些配置项的值格式非法"（只读快照，诊断用）✓

    🔑 **为什么要有这个 API**： ① **对现场有用** —— `grep CONFIG-DIAG` 只能看日志文本；本 API 让宿主/诊断页 可以**结构化查询**"到底哪几个键的值写错了、写成了什么"✓ ② **对测试有用** —— 守卫测试此前用**反射**读私有静态字段，实测在全量门禁下 **偶发 `Assert.NotNull() Failure: Value is null`** ✗（反射转型失败） ⇒ 改用本 API 后**彻底消除反射依赖** ⇒ 不再偶发红 ✓

    ⚠️ 返回的是**快照副本** ⇒ 调用方遍历时不会被并发写入影响 ✓

    ⚠️ **进程级静态**（非每设备）：同 key **同值**在全进程只告警一次； 同 key **异值**各自留痕（F-6 / A-295，多设备现场第 2 台不再静默）✓
