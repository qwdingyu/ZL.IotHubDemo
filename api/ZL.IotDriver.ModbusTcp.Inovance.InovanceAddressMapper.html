    Class InovanceAddressMapper

    汇川 Inovance 地址映射器。

    支持 AM / H3U / H5U 系列，地址格式：

    • D100 — 数据寄存器（FC3/FC6/FC16）
    • M0 — 内部辅助继电器（FC1/FC5/FC15）
    • X5 — 输入点（八进制，FC2）
    • Y10 — 输出点（八进制，FC1/FC5/FC15）
    • S100 — 状态继电器（FC1/FC5/FC15，仅 H3U/H5U）
    • T0 — 定时器线圈/当前值
    • C0 — 计数器线圈/当前值
    • SM0 — 特殊辅助（AM 专用）
    • SD0 — 特殊数据（AM 专用）
    • MB0 — 字中的字节（偶数地址）
    • MW0 — 字
    • MD0 — 双字

    Remarks

    [!!]【2026-11-14 审计结论】AM / H3U 两个系列的器件分支没有"官方范围守卫"，这不是遗漏： 仓内没有这两个系列的 Modbus 软元件地址表（19011157 编程手册只给"范围"、不给 Modbus 基址； HSL InovanceHelper 的 AM/H3U 路径同样只给基址、无范围校验） ⇒ 按项目纪律刻意不加 —— 凭猜加界会把合法地址判为越界，比"少加界"更糟。

    **已加守卫的**：`H5U/Easy` 系列（官方 `19011156` 手册有完整软元件范围表）。

    若将来取得 AM/H3U 的 Modbus 地址表：按 `MapH5UAddress` 的写法补 `> 上限 ⇒ return null`， 并补边界用例（参考 `InovanceH5URangeGuardTests`）。 审计台账见 `docs/drivers/品牌地址映射系统排查_缺陷类别与线索_20261114.md` §四点十六。

    HmiWriteFoldSupported

    该通道是否会把写 FC 改写为官方 HMI 码（默认 false = 拒绝 SM/SD 写）。

    [!] **只有具备 FC 改写钩子的通道才能设为 true**，否则跨区写（依据见上）。

    [!!]【为何是属性而非构造参数（AGENTS §21.5-1，实测打红 12 条）】第一版做成 InovanceAddressMapper(series, hmiWriteFoldSupported = false) ⇒ `AddressMapperHelperRadixTests` 用 Activator.CreateInstance **反射**构造（传 1 个参数）⇒ 抛 TargetParameterCountException （**反射不认可选参数默认值**）⇒ 构造签名**一字不动**，改用可设置属性 [OK]。

    [!!]【setter 收紧为 internal】误设 true 会让无钩子的通道放行 `SM`/`SD` 写 ⇒ 跨区写。 可写范围 = 本程序集 + `ZL.IotHub.Tests`（`AssemblyInfo.cs` 有 `InternalsVisibleTo`），其它程序集只读； 目前只有 `InovanceTcpDriver` 设为 `true`，`InovanceSerialDriver` 不设（保持 `false`）。
