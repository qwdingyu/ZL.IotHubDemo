    Enum DeviceFailureKind

    失败性质（跨协议统一）。用于下游做程序化分支（重试 / 告警 / 弃用点位）。

    🔴 设计原则：粒度只到"下游做决策所需"，不追求穷尽所有技术细节 ✗ —— 过细的分类会让驱动实现者无从判断，反而降低可靠性。

    Namespace: ZL.IotAbstraction.Abstractions
    Assembly: ZL.IotAbstraction.dll
    Syntax
    public enum DeviceFailureKind

    Fields

    Name Description
    AddressError

    地址错误：地址格式不被识别、区不支持、越界、解析失败。

    ⇒ **重试无意义** ✗ 应**修正地址** ✓（最常见的一类现场问题）
    ArgumentError

    参数/配置错误（调用方问题）：地址为空、写入值为 null、数组为空、长度非法等。

    ⇒ **重试无意义**（同样参数必然同样失败）✗ 应**修正点表/调用** ✓
    DataError

    数据异常：响应长度不足 / 帧校验失败 / 数据不完整。

    ⇒ **可重试一次**（可能是干扰），持续失败则说明配置或设备有问题 ✓
    DeviceRejected

    协议/设备拒绝：收到了响应，但内容表示失败（如 Modbus 异常码、设备返回错误码）。

    ⇒ **重试通常无意义**（设备明确拒绝）✗ 但可能是瞬时状态 ⇒ 视 `ErrorCode` 而定 ✓
    Disposed

    对象已释放：Dispose() 后继续使用。

    ⇒ **重试无意义** ✗ 应**重新创建实例** ✓（多为下游对象生命周期管理问题）
    NotConnected

    未连接：尚未 ConnectServer、连接已断开、对端关闭。

    ⇒ **应重试**（先重连）✓
    Other

    其它/未知：有明确错误但无法归入上述任何一类（如底层 IO 异常）。

    ⇒ 下游应按"保守策略"处理（可重试但需限次）✓
    Timeout

    超时：请求发出但未在时限内收到响应。

    ⇒ **可重试**，但需防雪崩（连续超时应降级设备）✓
    Unspecified

    未分类（默认值）。

    ⚠️ 含义是「**驱动没显式归类**」，不是"无错" ✓ ⇒ 下游**不得**把它当作"可忽略"；建议按 IsRetryable 决定 ✓
    Unsupported

    不支持：该驱动/协议未实现此操作（如只读设备的写、未实现的厂商功能码）。

    ⇒ **重试无意义** ✗ 属**功能边界**，不是故障 ✓
