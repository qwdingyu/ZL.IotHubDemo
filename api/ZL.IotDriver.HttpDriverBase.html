    IsConnected

    连接是否可用。

    ── 2026-09-20 修复（HTTP / MTConnect 协议完全不可用）──────────── 【缺陷】本类继承 NativeDriverBase，但**从不给继承来的 _socket 字段赋值**（本类全文 _socket 出现次数为 0）， 也未覆写 IsConnected。基类实现为： 

    !_disposed && _connected && _socket?.Connected == true

    _socket 恒为 null ⇒ IsConnected 恒为 false。 而 ReadString(string, ushort, Encoding) 首行即 IsReadyToOperate(...)（内部检查 IsConnected）， 于是所有读取都返回"未连接，请先调用 ConnectServer()"， 即使 ConnectServer() 已成功返回 IsSuccess=true。 已实测复现（本地 HTTP 服务返回 JSON）：

    ConnectServer(): IsSuccess=True
IsConnected = False                       ← 应为 True
ReadString(...): IsSuccess=False, "…未连接，请先调用 ConnectServer()"

    而 "http-rest" 与 "mtconnect" 都已在生产注册表登记 （NativeProtocolRegistry），即这两个协议此前 100% 取不到数据。

    【修法】覆写 IsConnected：HTTP 是**无状态请求/响应**协议， 不存在需要长期持有的 socket，故连接性只取决于"未释放 且 上次请求成功"。 这与本类 ConnectServer 只做 URL 可达性探测、以及 ReadString 成功后置 _connected = true 的既有语义一致。
