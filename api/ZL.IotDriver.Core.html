    PartialWrite

    [][][*] 分片写的"部分写入"披露（2026-11-16 建立，解决"多帧写非原子"这一结构性问题）。

    【问题的本质（不是 bug，是协议限制）】多数 PLC 协议（Modbus FC16/FC15、S7、FEnet、 EasyNet、Memobus、FX-Links、Keyence、Cimon、HostLink …）**单帧有长度上限且没有事务语义**。 因此"一次逻辑写超过单帧上限"**物理上不可能原子**： 第 k 帧失败时，前 k-1 帧已在 PLC 生效且**无法回滚**。

    ⇒ 既然**不可能**让它原子，唯一的彻底做法是让**"部分写入"结构上不可能被忽略**：

    1. **可预知的失败全部前置**到第 1 帧之前（长度、地址范围、片边界校验）；
    2. **任何**中途失败都必须由本类生成**显式披露**的文案（含"已写 X/Y 字节、N 帧"）；
    3. `IPlcDevice.WriteBytesAsync` 的契约写明这一点（见该接口 XML 注释）。

    【为什么用一个共享类，而不是每个驱动各写一句话】文案必须**格式统一**， 否则调用方无法可靠识别"这是部分写入"。单点定义也保证**新增分片驱动时不会漏写**。

    【复核命令】 

    grep -rn "PartialWrite.Fail" ZL.IotDriver --include=*.cs | wc -l   # 应等于分片驱动数

    SocketCloseHelper

    Socket 安全关闭的唯一实现。

    【为什么要它（docs/291）】"安全关闭 socket"这条规则此前在本仓有 **8 份实现**： SafeCloseSocket() 一份，另有 **7 个直接实现 IPlcDevice 的驱动各自私有的一份**。逐份比对发现它们**互不相同**， 其中最危险的分歧是：**5 份不会把 _socket 置空** ⇒ "安全关闭"之后仍留着 一个**已关闭的 socket 引用** ⇒ IsConnected 与后续连接复用都会看到不一致状态。 另有版本省略了 Connected 检查（对未连接 socket 调 Shutdown 会抛）。

    【本实现取"最防御"的语义】（即原 SafeCloseSocket() 的语义）：

    1. 仅当引用非空才处理；
    2. 仅在 Connected 为真时才 Shutdown（避免对未连接 socket 抛异常）；
    3. Shutdown 与 Close **各自独立 try** ⇒ 前者失败不影响后者；
    4. 最后把引用**置空** ⇒ 杜绝"已关闭引用"被复用。

    【调用方职责】_connected 之类的**状态位**由调用方按各自语义处理 （本仓既有实现一律先置 false，故调用方应在调用前完成），本方法只负责 socket 本身。

    TcpConnectHelper

    带超时的 TCP 连接（"异步 BeginConnect + 超时 + 失败即安全关闭"）的唯一实现。

    【为什么要它（docs/292）】该模式此前有 **3 份**几乎逐字相同的实现： NativeDriverBase 一份，另有两个**直接实现 IPlcDevice、不继承基类** 的驱动（MitsubishiMcDriver / OmronFinsDriver）各自复制一份。 三者都把 EndConnect 的异常**整个吞掉**（catch { }）⇒ 失败时调用方只看到"连接失败"这一句，**真实的失败原因（如 connection refused）被丢弃** ✗ —— 与本仓反复治理的"**静默**"族缺陷同源（docs/148 D-5、docs/283 §2）。

    【本实现的行为】**与原来逐条等价**，只多做一件事：**保留异常文本用于诊断** ✓

    1. IP 解析失败 ⇒ Fail("无法解析 IP: …")（原语义）；
    2. 超时 ⇒ 安全关闭 socket 后 Fail("连接超时(…ms)")（原语义）；
    3. 未连上 ⇒ 安全关闭 socket 后 Fail("连接失败: <真实原因>")（**新增原因** ✓）；
    4. 成功 ⇒ Ok（状态位由调用方自行置位）。

    失败路径统一复用 CloseSafely(ref Socket) ⇒ 与"安全关闭"同一条规则 ✓。

    WriteGate

    L3 写入授权门禁的统一入口 ✓。

    【为什么要它 ✗→✓】本仓 10 个驱动文件里，**19 处**逐字重复着同一段判断 ✓： 

    if (!LicenseGate.AllowWrite(_protocolKey))
    return LicenseGate.WriteDenied();

    —— 只有注释里的驱动名不同 ✗，判定逻辑完全一致 ✓。 ⇒ 收口后：改口径只需改一处 ✓；新增驱动也不容易漏 ✓。

    【⚠️ 与"有意分层"的区别 ✗】本项目此前曾把"许可门禁"整体判为"有意分层、不做收口"✗ —— 那个判断对 **L2（`EnsureLicensed`，抛 `LicenseException`）** 成立 ✓： L2 是"**根本不该运行**"✗、L3 是"**单次操作被拒**"✓，两者语义确实不同 ✓，不该合并。 但**本类只收口 L3 内部的重复写法** ✓ —— **不改变 L2/L3 的分层** ✗，**只把"L3 长什么样"收敛成一处** ✓。 两件事必须分清 ✗：**分层是语义 ✓，重复是写法 ✗**。
