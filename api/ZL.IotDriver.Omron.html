    OmronCpuUnitData

    欧姆龙 FINS 05 01「CPU UNIT DATA READ」的解析结果。

    【官方布局】OMRON W342-E1-15《Communications Commands Reference Manual》 §5-3-15「CPU UNIT DATA READ: 05 01」（PDF 第 190-191 页，仓内文本 docs/evidence/omron-w342_cs_cj_cp_nsj_communications_commands_reference_manual_en.pdftotext-layout.txt:12115）： 参数 00 时响应数据 = 20 字节型号 + 20 字节 CPU 内部系统版本 + 40 字节系统保留 + 12 字节区域数据，共 92 字节。

    【与 HSL 的差异】HSL 13.0.3 OmronCpuUnitData 把版本只取 10 字节 （data[20..29]），而官方明确型号/版本各 20 字节；本类按官方取 20 字节。 其余区大小字段与 HSL 一致（HSL 只暴露到 data[86]）。

    【证据等级】布局为 A 级（官方手册逐字段给出）；LargestEMNumber 的具体字节 位置为 B 级（官方仅给系统保留区图示，HSL 取 data[41]，未在真机核对）。

    OmronCpuUnitDataFull

    欧姆龙 FINS 05 01 无参数（读全部数据）的解析结果。

    【官方布局】OMRON W342-E1-15 §5-3-15（PDF 第 190-191 页）： 无参数时响应数据 = 参数 00 的 92 字节 + 参数 01 的 64 字节 CPU Bus Unit configuration，共 156 字节。

    【未解析部分】64 字节 CPU Bus Unit configuration 原样返回： 官方只说明“每个单元 2 字节（bit15 存在、bit0..14 型号 ID）+ 32 字节系统保留”， **未给出 16 位 ID 的字节序**；为避免猜错，本类不把 2 字节拆成 Present/ModelId， 由调用方按现场手册解释。CpuBusUnitConfiguration 长度恒为 64。

    【未验证】未在真实 NJ/NX/CJ 硬件核对。

    OmronCpuUnitStatus

    欧姆龙 FINS 06 01「读 CPU 单元状态」的解析结果。

    字段语义对齐 HSL 13.0.3 _vendor/hsl-decompile-13.0.3/HslCommunication.Profinet.Omron/OmronCpuUnitStatus.cs： Status（Run/Stop）、BatteryStatus（Present/No）、 CpuStatus（Normal/Standby）、Mode（PROGRAM/MONITOR/RUN）、 ErrorCode、ErrorMessage。

    【证据等级】字段偏移与 HSL 同源（B 级：单一实现），但本类只解析**有明确依据**的字段； 对响应长度不足的字段返回空/0，不猜测、不越界。仿真器的状态帧布局见 ZL.PlcSimulator/src/PlcSimulator.Lite/Protocols/Omron/OmronFinsUdpServer.cs 的 HandleCpuUnitStatus。

    OmronCycleTime

    Omron CPU 循环时间（FINS 06 20，参数 01）。

    官方单位是 0.1 ms：原始值 650 = 65.0 ms。 本 DTO 同时保留原始值（AverageRaw 等）与换算值（AverageMs 等）， 避免浮点四舍五入影响诊断比对。

    OmronFinsUdpDriver

    欧姆龙 FINS over UDP 驱动。

    FINS 帧构造/地址解析/数据类型转换**全部继承**自 OmronFinsDriver（与 TCP 版同帧 ✓）， 本类只把传输层从 TCP 流换成 UDP 数据报，并**去掉 FINS/TCP 头与握手** ✓

    ⚠️ UDP 无连接语义：ConnectServer() 仅记下默认对端， 不会因"对端未监听"而失败（UDP 特性，非缺陷）✓

    OmronHostLinkOverTcp

    欧姆龙 HostLink over TCP 协议驱动。

    参考: HSL OmronHostLinkOverTcp + OmronHostLinkHelper + OmronFinsNetHelper

    端口默认 9600。**16 个地址前缀**（全部经实测可解析 ✓，与 FINS 驱动**完全一致** ✓， 因为 HSL 里两者共用 `OmronFinsAddress.ParseFrom` —— 见 `docs/drivers/OmronHostLinkOverTcp.md`）。

    【前缀清单】`D`(数据寄存器) `DM` `C`(计数/裸短写) `CIO` `W` `H` `A`(短写) `AR` `T`(短写) `TIM` `CNT` `CF` `DR` `IR` `E`(EM) `EM`(≡ `E` ✓)

    【示例】`D100` `DM100` `CIO100.3`（位）`TIM10.3`（带位号 ✓）`CNT300` `CF5` `DR100` `IR100` `E0.100`（bank0 字100）`E1.100.3` `E10`（**十进制**字10）`EM10`（≡`E10`）

    ⚠️ 与 FINS 的差异：本驱动**只走 HostLink 帧**（`BuildFinsReadCommand` 内部复用 FINS 帧格式）， 地址语义与 FINS **一致** ✓；差异只在传输层封装 ✓。

    OmronHostLinkSerialDriver

    欧姆龙 HostLink 真串口驱动（omron-host-link-serial）。

    协议逻辑**全部委托**给 OmronHostLinkOverTcp 的 `internal` 纯函数 ⇒ 零复制 ✓

    地址语义与 `omron-host-link`（TCP）**完全一致**（同一 `ResolveAddress`）✓

    ⚠️ **未真机验证**（A=5 台但本机无设备）；与 TCP 版的一致性由共用编解码器保证 ⚠️
