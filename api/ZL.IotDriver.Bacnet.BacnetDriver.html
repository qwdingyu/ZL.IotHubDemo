    Syntax
    public sealed class BacnetDriver : NativeDriverBase, IPlcDevice, IDisposable, IFormattedStringWriter, IProtocolKey, IMultiTagReader
    Remarks

    地址方言：<device>.<AI|AO|AV|BI|BO|BV|MSV>:<实例>.<PV|PA|RD|NAME|UNITS|DESC>[.<数组索引>]， 例 1001.AV:1.PV、1001.AV:1.PA.8（优先级数组第 8 槽）。

    字节序铁律：BACnet REAL 是 IEEE-754 **大端**，与本框架 canonical 大端**一致** ⇒ 直接 BitConverter 反转一次即可，**不得再经 EndianConverter 二次转换** （仿真器侧踩过"多转一次读成 7.40218E-39"，见 `ZL.PlcBase/docs/drivers/Bacnet.md` §3）。

    UDP 语义：无连接 ⇒ ConnectServer() 只记录对端（不做握手）； 超时用重发代替重连；收端**整包**接收（一个数据报 = 一帧）。

    本版范围（M2）：ReadProperty / WriteProperty（PresentValue）+ 优先级数组读。 RPM 批量、COV 订阅、分段见 `docs/587` 的 M3/M4。

    Returns
    Type Description
    Task<DeviceResult<IReadOnlyDictionary<string, byte[]>>>
    Remarks

    为什么能显著减少往返：N 个标签若落在 M 个对象上 ⇒ 往返从 **N 次降到 M 次**； 同对象的多个属性（如 presentValue + units + objectName）**一次取回** ✓

    契约：只回成功项；失败标签不进字典（调用方可回退 ReadBytesCore(string, ushort) 逐点读）； 不抛异常（AGENTS §22.5 风格的显式错误）✓

    Remarks

    为什么必须有：BMS/SCADA 现场几乎默认用 RPM，逐条 ReadProperty 会被判"不规范"且慢 N 倍。

    ⚠️ 本实现按"对象"分组（我方仿真器与多数设备都支持一次 RPM 带多个对象， 但分组实现更保守、且能复用现有解析器）⇒ 最坏情况 = 对象数那么多次往返，仍远优于逐属性。
