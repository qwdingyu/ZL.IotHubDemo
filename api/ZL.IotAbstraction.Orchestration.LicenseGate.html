    Class LicenseGate

    IotHub 侧授权门禁（唯一推荐入口）。

    布尔逻辑在 AllowOperation(string)；本类补充 DeviceResult / 异常文案， 避免各驱动复制 !CommercialCheck() 判断与失败消息。

    分层约定： - 连接 L1：Allow(null) 仅状态通行； - 通信 L2：Allow(protocolKey) 带功能掩码；免费版策略仅在试用（Trial）态叠加； - 写入 L3：AllowWrite(protocolKey) 在 L2 之上收口（ 后免费版写入放行， 保留统一收口便于未来恢复禁写或按协议差异化授权）。

    2026-09-19 修复： ① 设备数判定已从免费版策略的每报文通路移除（准入统一在 ZL.License.LicenseManager.IncrementDeviceCount() 创建时原子判定）； ② 免费版策略增加 Trial 状态前提 —— 正式授权（Authorized）不再被 「设备数 ≥ 1 即拒」误伤。

    AllowWrite(string?)

    L3 写入门禁：在 Allow(string?) 之上收口写入。

    2026-09-19 修复：免费版「仅允许读取」曾是死规则 —— 写入口与读入口传同一个 protocolKey，IsWriteOperation 对白名单协议恒为 false，写禁令从未生效。所有 L3 写入口必须走本方法（收口仍保留， 即便已放开免费版写入，也便于未来恢复禁写/按协议授权）。

    WriteDenied()

    写入拒绝结果。

    🔴 2026-11-04 修真实缺陷：原实现只 `Fail(文案)` ⇒ 由文本推断得 Kind=DeviceRejected + Owner=Device ✗ —— 下游据此会去**查设备/网络**，而真相是**授权**问题 ✗✗ （实测：`"授权失效：写入被拒绝"` 含「被拒绝」⇒ 命中 `RejectedPattern`）

    ⇒ 显式指定：`Kind=DeviceRejected`（语义确实是"被拒绝"）+ `Owner=Capability`（责任方是**授权/能力**，不是设备）+ `FailureTag="License.WriteDenied"` ✓ —— 这正是把 `Owner` 设计成**独立维度**（而非由 `Kind` 唯一决定）的价值所在 ✓
