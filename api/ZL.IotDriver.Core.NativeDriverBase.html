    SendCore(byte[])

    【2026-10-21 新增 [OK]：无锁发送内核 —— 供「发 + 收」原子区间复用 [X]→[OK]】

    【为什么必须拆出它 [X]】`_ioLock` 是 `SemaphoreSlim(1,1)`，**不可重入** [X]。 而请求-响应类协议必须把「发 → 收」当作**一个原子区间** [OK]； 若驱动在外层 `_ioLock.Wait()` 后再调 `Send()`（它内部又 `Wait()`）⇒ **自死锁** [X][OK] —— 本会话实测踩过这个坑（给 `Dnp3`/`LSis` 直接套锁 ⇒ 立即构成死锁 [OK]）。

    【正确用法 [OK]】驱动在**自己持有的锁区间**内调 `SendCore`/`ReceiveCore` [OK]： 

    EnsureLicensed();
_ioLock.Wait();
try
{
    if (SendCore(cmd) is { IsSuccess: false } f) return f;
    return ReceiveCore(buffer, 0, len);
}
finally { _ioLock.Release(); }

    ⇒ 锁只取一次 [OK]，区间真正原子 [OK]，其它驱动照旧用 Send/Receive [OK]。

    【与既有设计一致 [OK]】基类本就有无锁的 SocketRead(int)（`:557`）[OK] —— 本节只是把同一思路补齐到**发送**侧 [OK]，不是新发明机制 [X]。

    [!] 调用方**必须**已持有 `_ioLock` 且已过授权 [OK]（本方法**不做**这两件事 [X]）。
