    Class PlcValidationTool

    PlcBase 事件链路验证工具。 在不依赖真实 PLC 的情况下，依次注入两轮标签值快照，校验：

    1. 标签加载是否正常
    2. 值变化检测 → PlcNotificationHub.Instance.TagChanges（UI 监控事件）是否触发 （注意：本工具的 PureSimDriver 自持缓存与变化检测，【不】调用 DeviceRoot.ProcessTagValueChange——那是 BatchEngine 的通路）
    3. TagType=M 的标签值变化后，OnTriggerDataChange（业务事件）是否触发
    4. PlcNotificationHub 是否收到变化事件，且携带正确 DeviceId

    RunFromTagFile(string, string, string, int)

    便捷入口：从 XML/JSON/CSV 标签文件直接运行验证（纯模拟，不连真实 PLC ✓）。

    🔴【2026-11-09 修复 docs/633 / A-241 缺陷二】**本方法此前必然返回 `Success=False`** ✗ —— 它自己构造配置时**漏填了 `Protocol` 与 `Port`**，而 Run(DeviceConfig) 把这两项判为**必填** ⇒ 实测对一份**完全正常**的点表也报： "缺少必填项 Protocol（协议名）" ＋ "缺少必填项 Port" ✗✗ ⇒ 而本方法的**唯一用途**正是"给下游做上线前点表自检" ⇒ 结果就是**下游每天看到"失败"**，工具形同虚设 ✗

    ✅ **修法**：补上这两个参数（**可选**，保持向后兼容 ✓）。

    ⚠️ **`protocolKey` 不只是"填个字段"** —— 它还参与**地址解析** （AddressInterpretation.Interpret(t.Address, protocolKey)）✗ ⇒ 若你的点表是 S7 地址（DB1.DBW0）而用默认的 modbus-tcp 解析， 会被误判为"地址不可解析" ⚠️ ⇒ **请按点表实际协议传入**；用默认值时报告里会加一条**警告**提醒你 ✓
