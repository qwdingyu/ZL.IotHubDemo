    Remarks

    为什么"只换传输"是安全的：Modbus 的 UDP 形态（俗称 Modbus/UDP 或 MBAP over UDP） 与 TCP 形态的**应用层帧完全一致** —— 同样的 MBAP 头（事务号/协议号/长度/单元号）+ 同样的 PDU。 因此地址解析、功能码、异常码、字节序**全部复用** ModbusTcpDriver， 本类只覆写三处：连接语义、可达性判定、收发。

    🔴 关键差异（照抄 TCP 的两段式收会出错）：

    1. 不能分两次 Receive：UDP 是**数据报**语义，Receive(7 字节缓冲) 会把 整个数据报的其余部分**丢弃**（不像 TCP 流可以继续读）⇒ 必须先收**整报**再解析 ✗
    2. 无握手：UDP 没有三次握手 ⇒ "连接"只是**记下默认对端**（Socket.Connect(host,port)）✓
    3. 无断线信号：TCP 的 Receive 返回 0 表示对端关闭；UDP 不会返回 0 ⇒ 用**超时重发**代替 TCP 的重连（默认重发 1 次）✓
    4. 一报一帧：UDP 天然按数据报对齐 ⇒ 不存在 TCP 的"半截帧残留在流里"问题， 但也**不能**靠"丢弃连接"清理错位 ⇒ 事务号/单元号不符时只能丢弃**该报**并报错 ✓

    与 OmronFinsUdpDriver 同款套路（本仓成熟先例）： 继承 TCP 驱动，只覆写 CreateSocket/ConnectSocket/SendAndReceive 这一层 ✗ —— 但 Modbus 的 TCP 实现把 _socket.Receive 写在**私有** core 里且是两段式， 无法直接复用 ⇒ 本类改为**整体覆写 SendAndReceive**（唯一的 I/O 汇点）✓

    验证方式（2026-11-05）：`CrossTest/ModbusUdpCrossTests` —— 测试内**自建 UDP 从站**（按规范手写，非仿真器）+ **HSL `ModbusUdpNet` 当裁判**， 三方独立实现；因仿真器仓当期不可用（其 AB 服务端在途改动崩溃），本项**不依赖仿真器** ✓
