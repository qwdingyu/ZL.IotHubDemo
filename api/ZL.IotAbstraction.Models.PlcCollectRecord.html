    Class PlcCollectRecord

    通用采集数据快照——一次批量采集的完整结果。

    在工控场景中，通常以"设备 + 工位"为维度，每个采集周期读取一批点位， 然后将结果打包为一个 PlcCollectRecord，交由上层（MES 入库、SCADA 显示、日志持久化）消费。

    设计要点： - Values 字典使用 OrdinalIgnoreCase 比较器，因为 PLC 地址不区分大小写（"DB1.DBD0" == "db1.dbd0"）； - MainCode 用于产线场景：当驱动层已识别到产品序列号时，可直接关联采集数据与产品追溯。

    Qualities

    每点位的质量码映射（TagId → 质量名：Good / Uncertain / Bad / Initializing）。

    🔴🔴【2026-11-11 N-4 新增】`Values` 只有值、没有可信度 ⇒ 归档消费者 （MES 入库/数据上报）会把**降级点的冻结最后值**当实时可信数据 ✗。 与 `Values` 并行提供质量码（OPC「值 + 质量」双维惯例）， **消费侧按自身容错过滤**（fail-closed 场景：非 Good 不入库/标疑）。

    ⚠️ 为什么不改成"跳过非 Good"：会破坏"键齐全"的既有口径 —— 值与质量两维各自完整才可对账（缺值无法区分"没采到"与"坏了"）。

    向后兼容：增量字段，旧消费者忽略即可；键与 `Values` 同源同名。
