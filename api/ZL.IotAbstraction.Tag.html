    ConfigDiagnostic

    【A-257】配置装载期诊断的统一标识 —— 单一来源，全仓必须引用本常量，不得各自写字符串 ✗

    🔑 **为什么需要它**（这是"不要局部无止境打补丁"的关键）： 本仓已修 4 处"装载期吞错"缺陷（A-253 键名 / A-254 值格式 / A-255 点表条目 / A-256 插件诊断）， 它们的修复**各自打了日志**，但**格式不统一** ⇒ 现场排查时**无法一条命令找全** ✗ ⇒ 统一标识后：**`grep CONFIG-DIAG` 即可列出本次启动的全部配置问题** ✓

    ⚠️ **必须是常量，不能各处手写 `"[CONFIG-DIAG]"`** ✗ —— 本仓已因"多处手写同一语义"踩过坑（配置键 `IP`/`Ip` 大小写漂移、`SupportedAreas` 有表无人读）。 手写字符串 ⇒ 迟早出现 `[CONFIG_DIAG]`/`[CONFIGDIAG]` 等变体 ⇒ grep 又找不全 ✗✗

    ⚠️ **只用于【配置装载期】**（`DeviceConfig` 读取 / `TagKit` 点表装载 / `DeviceRoot.Initialize` / 插件装载）—— **不用于运行期韧性代码**（如 `Dispose`/`Close` 里的"尽力而为"catch）✗ 后者吞错是**正确设计**，不应被标记为配置问题 ✓

    📌 **现场排查第一步**：`grep "CONFIG-DIAG" 日志文件` ⇒ 得到本次启动的全部配置问题（含修正建议）✓

    DeviceConfig

    通用设备配置容器。

    使用 Dictionary 灵活存储任意键值对配置参数（IP、端口、标签路径、扫描间隔等）， 支持从 JSON 文件、数据库或上层应用动态构造后注入到 DeviceRoot/DevicePro。

    线程安全说明：本类本身不是线程安全的，应在设备构造阶段（单线程）完成所有配置写入， 运行时仅做只读访问。如需热更新配置，由调用方负责加锁。

    TagTypeHelper

    TagType 的唯一真源（禁止再在业务代码里散落 "M"/"HB"/"RO" 魔法字符串）。

    🔴 **为什么必须收敛（2026-10-30 实测）**：改动前"是否监控标签"这一语义在 本仓被**重复实现了 12 处**，且用了**三种互相冲突的策略**：

    • 区分大小写 tag.TagType == "M" —— 4 处： DevicePro.cs、DeviceRoot.cs（采集热路径）、BatchEngine.cs ×2
    • 不区分大小写 string.Equals(..., OrdinalIgnoreCase) —— 7 处： TagItem.cs、TagKit.cs ×3、PlcValidationTool.cs ×3
    • switch (TagType?.ToUpperInvariant()) —— 1 处：DeviceRoot.cs 分桶

    ⇒ 实测后果：点表写 TagType="m" 时，标签**能进 TriggerTags、 还会被置 IsTrigger=true**，但**不进入 triggerChanges** ⇒ 触发回调**静默失效**、日志无任何提示，现场极难排查。

    ✅ **根治方式（双保险）**：

    1. TagType 的 setter **写入即归一化**（去空白 + 转大写） ⇒ 无论 XML/CSV/JSON/代码赋值，下游看到的**永远是规范大写**；
    2. 判定**一律走本类**（IsMonitor(string) 等）⇒ 即使将来有人绕过 setter， 语义也不会漂移。

    StringKind

    字符串存储格式枚举。

    西门子 S7 系列 PLC 的字符串存储有三种格式： - Raw：无前导符模式，直接存储字符数据（S7-200、Modbus 等） - S7String：西门子 STRING 格式（S7-1200/1500），前 2 字节为元数据 - S7WString：西门子 WSTRING 格式（S7-1200/1500），前 4 字节为元数据

    【设计目的】将字符串格式判断从设备级（DeviceRoot.DefaultStringKind）下沉到标签级， 使同一台 PLC 上可以混合使用不同格式的字符串标签。 例如 S7-1500 上可同时存在 String[20]（2 字节头）、Array of Char（无头）、WString[20]（4 字节头）。

    TriggerModeKind

    触发边沿模式（TagItem.TriggerMode 的规范语义）。 Rising=上升沿（false→true / 0→1），Falling=下降沿（true→false / 1→0），Both=双边沿（任意变化）。 注意：本枚举表达“边沿检测方向”，不代表“是否启用触发”；是否启用由 TagType=M 表达。
