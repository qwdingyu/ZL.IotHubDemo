    Class KeyenceMcDriver

    基恩士 MC 协议驱动。基于三菱 MC 协议，基恩士 KV-7500/5500 等系列使用。 地址格式：MR0, LR0, CR0（基恩士专用的继电器/寄存器类型）。

    **MR / LR / CR / CM 已实现** ✓（2026-10-21，依 HSL 12.9.2 `ParseKeyenceFrom` + 码值表）。 `MR/LR/CR` 的编号是**复杂地址**（2026-10-23 修正 ✗→✓）：无点号且长度 > 2 时 按 `前段 × 16 + 末两位十进制`（如 `MR100` ⇒ **16**，不是 100 ✗）；带点号时 按 HSL `CalculateComplexAddress` 处理末段（含 A-F 用 16 进制）✓。

    ⚠️ **可信度边界**：码值与复杂地址语义均来自 HSL 12.9.2 反编译，**未经真机验证** ⇒ 对外只能标“依 HSL 实现”，不得声称“已验证” ✗。详见 ParseAddress(string) 内注释。

    ⚠️⚠️ **必须知道的使用陷阱（2026-11-10 全局审查补充）**： 除 ZR / MR / LR / CR / CM 外，**其余前缀一律走 `fallback` = 三菱 MC 的解析器** ⇒ 按**三菱区域码**下发 ✗

    **为什么是这样**（不是缺陷，是参考实现如此）：HSL 的 KeyenceMcNet : MelsecMcNet **直接继承**，只对布尔地址做额外判定，其余完全复用三菱解析 ✓ ⇒ 我方 `ParseKeyenceAddressCore(address, fallback)` 与该语义一致 ✓

    **后果**：`SM100` / `SD100` / `X100` 这类在**三菱**里合法的写法， 本驱动**不会报错**，而是按三菱区域码发出去 ⇒ 若目标基恩士 PLC 上该区不存在或含义不同 ⇒ 可能**读到错误的区，且 `IsSuccess = true`** ✗✗ ⇒ **点表请只用 `MR` / `LR` / `CR` / `CM` / `ZR`**； 确需其它区时，**先对照基恩士手册确认区域码与三菱一致**后再用 ✓
