    Class NativeProtocolDescriptor

    原生协议画像：把"设备类型差异"从驱动主逻辑中剥离的策略对象。 不同 PLC 协议（西门子、三菱、欧姆龙等）在客户端创建方式、地址格式、字节序等方面存在差异。 本类将这些差异封装为可插拔策略，使 NativeUnifiedDriver 能以统一逻辑驱动所有协议。

    PreserveSourceAddress

    【2026-10-21 新增】本协议的驱动地址必须取自【原始地址串】（而非 BatchAddressFormatter(DataBlock, StartByte) 拼出来的）✓。

    【为什么需要】**名称型寻址**协议的地址就是「标签名 / JSON 路径 / 数据项 id」✓， 驱动**原样**使用它 ✓（实测：`HttpRestDriver`/`MTConnectDriver` 把 `address` 直接交给 `ExtractJsonPath(address)` ✓）。而 `PlcAddressHelper` 解析时会把 **区域字母归一为大写** ✗ ⇒ `Pump1` 经「解析 ⇒ 拼接」变成 **`PUMP1`** ✗✓ ⇒ 会去请求**另一个（多半不存在的）点** ✗。

    【为什么不能对所有协议都这样】✗ 实测：Modbus 的 `40001` 解析后 `ByteOffset=0` ✓（**一基归一发生在解析阶段** ✓）；若改用原串 `"40001"`， 驱动会去读**寄存器 40001** ✗✓（`ResolveAddress("40001")`=40001 ✗、`("0")`=0 ✓） ⇒ **寄存器型协议必须用拼接结果** ✓。故本开关**按协议**开启 ✓，默认 `false` ✓。

    生效条件：**块内恰有 1 个标签** ✓（多标签块无法用单一原串表达 ✗）。

    UseAreaAwareRead

    启用「带区语义读取」。默认 false。

    🔴 为什么需要这个开关：某些协议的数据区**不体现在地址文本里** （Modbus 用功能码表达区），而 `BatchAddressFormatter` 只输出裸寄存器号 ⇒ 区信息丢失 ⇒ 驱动恒用 FC3 ⇒ **静默读到错误的区** ✗✗

    开启后：建块时把 Addressing.PlcReadBlock.NativeArea 填上， 采集引擎若发现驱动实现了 Core.IAreaAwareReader 就走 ReadBytesInArea（**区与偏移分开传，不经过字符串**）✓

    ⚠️ 默认 false ⇒ 其余协议行为逐字节不变（结构性保证）✓
