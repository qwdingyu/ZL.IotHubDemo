    Class AllenBradleyCipDriver

    Allen-Bradley ControlLogix / CompactLogix CIP 协议纯 C# 驱动程序。

    直接基于 TCP Socket 实现 CIP 协议（EtherNet/IP），无需 libplctag 原生依赖。 协议帧结构对齐 HSL Communication 官方实现：PackRequestHeader + PackCommandService + PackCommandSpecificData。 支持全局标签、程序标签（Program:xxx.yyy）、数组元素（Tag[0]）等地址格式。

    ReadFragmentedAsync(string, uint, ushort)

    分段读取大数组（CIP 0x52 Read Tag Fragmented）。

    请求体：52 + path + length(2B LE) + startIndex(4B LE)； 响应 General Status 为 0x06（Partial transfer）时，按已返回字节数推进 startIndex 继续请求，直到状态为 0x00。

    ReadManyAsync(IReadOnlyList<(string Address, ushort Length)>)

    批量读取多个标签（单次 EtherNet/IP 事务，CIP Multiple Service Packet）。

    【契约】length 是**字节数**（与 ReadBytesAsync(string, ushort) 一致）； 返回字典只包含成功的项，重复地址后者覆盖前者，任何一项失败都**不抛异常**。

    【实现边界】CIP 读请求的 count 字段是**元素个数**，而本驱动无法在不知道标签 类型的情况下把字节数精确换算成元素数。为保持与既有单读路径 ReadBytesAsync(string, ushort) 完全相同的语义（docs/216：把请求字节数当元素数， 再按字节截断），这里也把 length 直接作为元素数发送，并按每项 length 字节截断响应。对 SINT/BOOL 等 1 字节元素精确；对 DINT/REAL 会多读若干元素，但不会少读，也不会改变对外返回的字节数。

    【为什么不逐项调用单读】单读 N 个标签要 N 次往返；Multiple Service Packet 把 N 个请求装进一帧，是 HSL AllenBradleyNet.Read(string[], ushort[]) 同款做法（_vendor/.../AllenBradleyHelper.PackCommandService(portSlot, cips)）。

    ReadStringAsync(string, ushort, Encoding)

    读取 Logix STRING。

    【2026-09-29 重写，docs/217】按**真机实测的标准布局**解码： STRING := { LEN : DINT ; DATA : SINT[n] }，即 LEN 在结构偏移 0（4 字节），DATA 在结构偏移 4。

    依据（CompactLogix 5069-L330ERM fw38 真机探针，见 rust-ethernet-ip docs/validation/2026-07-02_string_write_probe_5069-L330ERM_fw38.md）： 结构实例 88 字节 = LEN 4 + DATA 82 + 2 补齐；B1 用 86 字节被拒（0x13）、 B2 用 88 字节成功，据此精确确定了补齐量与成员偏移。

    [!] 旧实现从偏移 2/6 解码（LEN@2、字符@6），与真机布局不符。 该约定来自 HSL 的 TransInt32(content,2) + GetString(content,6,n)， 但 HSL 该偏移只适用于其自身 218 分支的上下文，并非 Logix STRING 结构。 现按标准布局解码，并保留"整段裸字符"兜底（模拟器或第三方未建模 LEN 时）。

    WriteAsync(string, string, Encoding)

    写入 Logix STRING —— 采用 HSL 的成员写方案。

    【2026-09-29 重写，docs/217】分两步：

    1. Write(Tag.LEN, n) —— 把字符长度写进 LEN 成员（DINT）；
    2. WriteTag(Tag.DATA[0], 0x00C2 /*SINT*/, chars, n) —— 把字符写进 DATA 数组。

    依据（CompactLogix 5069-L330ERM fw38 真机探针）：

    • 策略 D「.DATA 整段 82 元素 SINT 写 + .LEN DINT 写」→ [OK] general 0x00，回读一致；
    • 策略 B2「整体写，结构类型 0x02A0 + 句柄 0x0FCE，88 字节」→ [OK]；
    • 策略 A「整体写，原子类型 0x00CE，无补齐」→ [X] 0xFF/0x2107。

    选成员写而非整体写的原因：句柄随字符串类型而变（内置 STRING 0x0FCE， 自定义 Str82 为 0x9621），猜错即 0x2107；而成员写 由控制器自行解析成员，不依赖句柄，对内置与自定义类型都成立。 这也正是 HSL 10.6.1 / 12.9.2 的做法 —— 与业界标准、与 HSL 参考方案一致。

    旧实现（537e1cf）的整体写 [2B 前缀][LEN][chars] + 原子类型 0x00D0 带有**凭空多出的 2 字节前缀**，与真机布局不符，真机预计返回 0xFF/0x2107。已移除。
