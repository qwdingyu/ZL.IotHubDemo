    TryGetAddressSemantics(string, string, out DeviceAddressSemantics)

    【2026-10-23 新增】带数据类型提示的语义解析 —— 供「位/字双用途」地址使用 ✓。

    【为什么必须要它 ✗→✓ 实测缺陷】有些地址**同一串可以是位也可以是字**： * Modbus 裸数字 `800`：`ReadBool("800")` 读**线圈 800**、`ReadInt16("800")` 读**寄存器 800** —— 两个**完全不同**的区域 ✗ * ⇒ 只看地址串**无法**决定语义 ✗；必须由调用方告知"这个标签是什么类型" ✓

    ⚠️ **本仓 TFM 含 `netstandard2.0`，不支持 default interface method（实测 `CS8701`）** ✗ ⇒ 这是**抽象成员**，每个实现类都必须提供 ✓。 不涉及双用途地址的驱动，直接写 `=> TryGetAddressSemantics(address, out semantics);` 转调 ✓ （见 `MitsubishiMcDriver`）。

    【实测佐证】若不区分：`800 + int16` 建块得 `StartByte=50`（按**位号** 800/8/2 算）， 而正确应是 `StartByte=800`（**寄存器** 800）⇒ 读错位置 ✗。
