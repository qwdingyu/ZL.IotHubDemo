    Class PlcReadBlock

    PLC 批量读取块。 在工业现场，逐标签读取 PLC 数据会导致大量网络往返，严重影响采集效率。 PlcReadBlockBuilder 会将地址相邻的标签合并为一个读取块， 一次网络请求读取连续字节区域，再由 PlcValueExtractor 从 buffer 中提取各标签值。

    AddressUnitBytes

    本块的地址单位字节数：1 = 字节寻址（西门子 S7 / Beckhoff ADS）； 2 = 字寻址（Modbus / 三菱 / 欧姆龙 / Fatek / LSis / Panasonic / Delta / Inovance / Xinje / Keyence）。

    【2026-10-20 新增，docs/436 §九】用于统一"地址以原生单位存储、长度以字节计算"的口径： `Length`（字节）= 跨度（单位）× 本值。缺了这个换算， 相邻字点位合并后第 2 个起点位会**取值错位**（实测 T2=0x1122，应为 0x2222）✗

    BufferByteStart

    块缓冲区的起始字节偏移（取值器算 rel 的基准）。-1 表示未设置 ⇒ 取值器退回 StartByte * AddressUnitBytes（即改动前的行为）。

    为什么需要（2026-11-17 实测缺陷）：`ResolveBlockAddress` 对 preserveSource 的**单标签块 / 全位块**返回**首标签的原始地址串** （如 MC 的 `B1F`）⇒ 驱动被要求 ReadBytes("B1F", 1) ⇒ 返回的那 1 字节 **就是 `B1F` 自己的字节**。而取值器此前一律用 StartByte * unit 作基准， 对位地址该值被 ByteOffset / unit **截断**过 ⇒ 基准偏小 ⇒ rel 偏大 ⇒ rel >= Length ⇒ **该点位永远无值**。 实测 `B1F`：`ByteOffset=3`、`unit=2` ⇒ `StartByte=1`、基准=2、`rel=1`，而 `Length=1`。

    为什么不在建块器里定：缓冲区起点取决于**是否用了源地址**， 那是**设备级**属性（DeviceRoot.PreserveSourceAddressOnSingleTagBlock）， 建块器看不到 ⇒ 只能在 `DeviceRoot.BuildPlan` 解析完地址后填。

    默认 -1 的安全性：未设置 ⇒ 完全走原逻辑 ⇒ 对**所有**不经过本字段的 调用点（含既有测试）**零行为变化**。

    StartByte

    本块起始位置（以"地址单位"计，相对于数据区）。

    ⚠️ **不要假设它是字节** ✗：对字节寻址协议（西门子/ADS）单位=1 字节； 对字寻址协议（Modbus/三菱/欧姆龙/Fatek/LSis…）单位=1 个字（2 字节）。 该值**直接用于拼驱动的地址串**（`FormatBatchAddress`），故必须保持协议原生单位。

    字节位置 = StartByte × AddressUnitBytes。
